Output Formats: Reports and exports support multiple formats via the format query parameter: html (default), excel, or json. JSON Schema definitions are available at /schemas/.
Pagination & large exports: list reports are paginated — use page and page_size (default 100, max 1000); the HTML view shows Prev/Next controls. Add all=true to return the full result set: the HTML view still pages, while excel/json exports stream the entire set page-by-page so memory stays flat on large datasets.

Ingestion Endpoints
These endpoints accept POST requests with JSON bodies. Use Authorization: Bearer <token> for authentication. Async by default: all four POST /ingest/* endpoints return 202 Accepted with a job_id and status_url; the heavy parse-and-persist work runs on the dedicated enrichment-ingest-worker Celery pool. Poll GET /ingest/jobs/<job_id> for the terminal summary. Pass ?sync=true to force the legacy synchronous path and receive a 201 Created with the summary inline (use only for small SBOMs in scripts). See docs/ingest-pipeline.md for the full contract.
POST /ingest/cyclonedx Upload and process a CycloneDX SBOM. Parses components, dependencies, and defects into...
Upload and process a CycloneDX SBOM. Parses components, dependencies, and defects into the graph. SBOM provenance (document hash, tool info) is stored and linked to ingested versions.
Body: {"sbom": <CycloneDX JSON>, "app_id"?: string, "public_app_id"?: string, "project_url"?: string}.
Query: ?sync=true (optional) forces synchronous processing.
Response 202 (default): {status, record_id, job_id, status_url, format}.
Response 201 (?sync=true): {status, record_id, format, projects_count, dependencies_count, defects_count}.
POST /ingest/spdx Upload and process an SPDX 2.3 JSON SBOM. Parses packages, relationships, licenses, sou...
Upload and process an SPDX 2.3 JSON SBOM. Parses packages, relationships, licenses, source repos, and defects into the graph. SBOM provenance is stored and linked to ingested versions.
Body: {"sbom": <SPDX 2.3 JSON>, "app_id"?: string, "public_app_id"?: string, "project_url"?: string}.
Query: ?sync=true (optional). Async and sync response shapes match /ingest/cyclonedx with format: "spdx".
POST /ingest/sbom Auto-detect SBOM format (CycloneDX or SPDX) from the document structure and process acc...
Auto-detect SBOM format (CycloneDX or SPDX) from the document structure and process accordingly. Use when format is unknown or tools may produce either format.
Body: {"sbom": <CycloneDX or SPDX JSON>, ...}. Format detected via bomFormat/metadata.component (CycloneDX) or spdxVersion (SPDX).
Query: ?sync=true (optional). Response includes detected format.
POST /ingest/vex Upload an OpenVEX document. Parses VEX statements and links them to existing vulnerabil...
Upload an OpenVEX document. Parses VEX statements and links them to existing vulnerabilities.
Body: OpenVEX JSON document.
Query: ?sync=true (optional). Async response: {status, record_id, job_id, status_url} (no format key).
GET /ingest/jobs/<job_id> Status of an asynchronous ingest job. Poll until terminal: true.
Status of an asynchronous ingest job. Poll until terminal: true. state values: PENDING, RECEIVED, STARTED, SUCCESS, FAILURE, REVOKED.
Path: job_id must be a UUID (returned from a prior POST /ingest/*).
Response (terminal SUCCESS): {job_id, state: "SUCCESS", terminal: true, result: {status, record_id, format, projects_count, dependencies_count, defects_count}}.
Response (FAILURE): {job_id, state: "FAILURE", terminal: true, result: {status: "error", error: <sanitised message>}}.
Errors: 400 if not a UUID; 503 if the ingest pipeline is not installed.
