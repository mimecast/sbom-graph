Output Formats: Reports and exports support multiple formats via the format query parameter: html (default), excel, or json. JSON Schema definitions are available at /schemas/.

Query Parameters Reference

ParameterTypeDefaultDescription
formatstringhtmlOutput format: html, excel, or json
internal_onlybooleanfalseSet to true to show only internal-labeled nodes
latest_onlybooleanfalseFor /reports/applications: show only the latest version per application
longest_onlybooleantrueFor /reports/dependants: show only the longest paths (for vulnerability prioritization)
layoutstringspring/radialVisualization layout: spring, radial, shell, bfs, circular
sort_bystringinDegreeFor /reports/centrality: inDegree, outDegree, project_name, version_name
sort_orderstringdescFor /reports/centrality: asc or desc
max_depthinteger15Maximum traversal depth (1-100)
limitinteger10000Maximum number of results (max: 100000)
heightstring100vhVisualization height (CSS dimension)
widthstring100vwVisualization width (CSS dimension)

Visualization Endpoints

GET /visualizations/kpartite/{project_name}/{version}
K-partite visualization of transitive dependencies with color-coded partition levels
Params: max_depth, internal_only, height, width
GET /visualizations/bipartite/{project_name}
Bi-partite graph of project versions and their direct dependants
Params: internal_only, height, width
GET /visualizations/dependants/{project_name}/{version}
Full dependants graph showing all projects that depend on this version
Params: max_depth, internal_only, height, width
GET /visualizations/dependencies/{project_name}/{version}
Dependencies graph with multiple layout options and cycle detection. Cycle edges are highlighted in red with dashed lines. Includes interactive layout switcher.
Params: layout, max_depth, internal_only, height, width
GET /visualizations/dependants-multi/{project_name}/{version}
Dependants graph with multiple layout options and cycle detection. Shows all projects that depend on this library. Includes interactive layout switcher.
Params: layout, max_depth, internal_only, height, width

Report Endpoints

GET /reports/version-dependencies/{project_name}/{version}
Shows all transitive dependencies for a version (what it depends ON). Use latest for the latest SemVer version (only if ALL project versions are SemVer compliant).
Params: format, internal_only, max_depth
GET /reports/projects
Table view of all projects with versions
Params: format, limit, internal_only
GET /reports/applications
Table view of all applications (root nodes) with versions and metadata
Params: format, limit, internal_only, latest_only
GET /reports/snapshots
Report of applications with SNAPSHOT dependencies
Params: format, internal_only
GET /reports/self-dependencies
Report of nodes that depend on themselves
Params: format, internal_only
GET /reports/multi-version-deps/{project_name}
Library version adoption report - shows all versions of a library and who uses each. Use for vulnerability remediation planning.
Params: format, internal_only
GET /reports/multi-version-sources/{project_name}/{version}
Diamond dependency analysis - shows version conflicts within a project's dependency tree. Use to find runtime conflict risks.
Params: format, max_depth, internal_only
GET /reports/non-semver-versions
Report of versions not following SemVer naming convention
Params: format, internal_only
GET /reports/dependants/{project_name}/{version}
Report of all dependants with partition levels and dependency paths (longest paths for vulnerability prioritization)
Params: format, max_depth, internal_only, longest_only (default: true)
GET /reports/vulnerabilities
Report of all vulnerabilities ordered by severity with affected versions. Links to dependant visualizations and impact reports.
Params: format, internal_only
GET /reports/vulnerability-dependants/{defect_id}
Report of all dependants affected by a specific vulnerability, ordered by partition (distance from vulnerable library)
Params: format, max_depth, internal_only
GET /reports/centrality
Centrality metrics (inDegree/outDegree) for internal libraries. inDegree = projects depending on this, outDegree = dependencies. Includes drill-down links to visualizations.
Params: format, sort_by, sort_order, limit
GET /reports/licenses
All licenses grouped by risk category (Copyleft, Weak Copyleft, Permissive, Unknown)
Params: format, internal_only
GET /reports/license-summary/{project_name}/{version}
License BOM for a specific project version, including transitive dependency licenses
Params: format, max_depth, internal_only
GET /reports/vulnerability-freshness
Enrichment freshness report showing packages whose vulnerability data is older than a configurable threshold
Params: format, internal_only
GET /reports/policy-violations
All packages with ‘bad’ policy annotations that are still in use as dependencies
Params: format, internal_only
GET /reports/vex-coverage
VEX coverage statistics showing how many vulnerabilities have VEX statements and their status breakdown
Params: format, internal_only
GET /reports/license-conflicts
Projects mixing incompatible license categories in their dependency tree
Params: format, internal_only
GET /reports/source-repos
All tracked source repositories with linked package counts
Params: format

Ingestion Endpoints

These endpoints accept POST requests with JSON bodies. Use Authorization: Bearer <token> for authentication.
POST /ingest/cyclonedx
Upload and process a CycloneDX SBOM. Parses components and dependencies into the graph.
Body: CycloneDX JSON document. Optional fields: scan_id, application_name, gitlab_project_url
POST /ingest/spdx
Upload and process an SPDX 2.3 JSON SBOM. Parses packages and relationships into the graph.
Body: SPDX 2.3 JSON document. Optional fields: scan_id, application_name
POST /ingest/sbom
Auto-detect SBOM format (CycloneDX or SPDX) from the document structure and process accordingly
Body: CycloneDX or SPDX JSON document. Format is detected automatically.
POST /ingest/vex
Upload an OpenVEX document. Parses VEX statements and links them to existing vulnerabilities.
Body: OpenVEX JSON document

Programmatic API (v1)

JSON-only endpoints under /api/v1/ designed for CI/CD pipelines and programmatic consumption. All endpoints require JWT authentication via Authorization: Bearer <token>.
GET /api/v1/package/{purl}/licenses
Licenses for a specific package identified by Package URL
GET /api/v1/package/{purl}/vulns
Vulnerabilities for a package, optionally including transitive dependency vulnerabilities
Params: include_dependencies (boolean, default false)
POST /api/v1/enrich/vulnerabilities
Trigger on-demand vulnerability enrichment for all or specified packages. Dispatches async enrichment tasks.
Body (optional): {"purls": ["pkg:maven/..."]} — omit to enrich all packages
POST /api/v1/policy/annotate
Create a policy annotation (certifyBad / certifyGood / hold) on a package
Body: {"purl": "pkg:...", "type": "bad"|"good"|"hold", "justification": "...", "expires_at": "..."}
DELETE /api/v1/policy/annotate/{annotation_id}
Revoke a policy annotation by its ID
GET /api/v1/patch-plan/{defect_id}
Frontier-level patch plan for a vulnerability. Shows which packages to patch and in what order.
Params: max_depth (default 10), internal_only
GET /api/v1/blast-radius/{purl}
Blast radius analysis for a compromised package. Shows all affected dependants by distance.
Params: max_depth (default 10), internal_only
POST /api/v1/contacts
Create a point of contact linked to a package for incident response
Body: {"email": "...", "purl": "pkg:...", "team": "...", "slack_channel": "..."}
GET /api/v1/package/{purl}/vex
VEX (Vulnerability Exploitability eXchange) statements for a package's vulnerabilities
GET /api/v1/package/{purl}/policy
CI/CD gate: check policy status for a package. Returns pass/fail/hold verdict with annotations.

Supply-Chain Trust Score API

Composite trust scores combining OpenSSF Scorecard, OSV, Sonatype OSS Index, and deps.dev. Scores range from 0 (worst) to 10 (best) with inherited risk propagation through the dependency graph.
GET /api/v1/package/{purl}/trust-score
Full trust score breakdown: direct score, effective score (with inherited risk), per-category scores, confidence level
GET /api/v1/package/{purl}/trust-score/risk-path
Top dependency chains contributing most to score degradation. Answers: “Why is this score low and what should I fix first?”
Params: limit (default 10, max 50)
GET /api/v1/application/{purl}/supply-chain-risk
Aggregate supply-chain risk for an application: effective score, weakest-link package, top risk contributors
GET /api/v1/analysis/trust-score-distribution
Histogram of effective trust scores across all packages for portfolio-level risk assessment
GET /api/v1/analysis/remediation-priorities
Packages ranked by remediation leverage: the number of applications that would improve if each package were upgraded
Params: limit (default 20, max 100)
GET /api/v1/package/{purl}/trust-check
CI/CD gate: check if a package meets minimum trust score thresholds. Returns pass/fail with score details.
Params: min_score (default 5.0), min_confidence (default 0.25)
